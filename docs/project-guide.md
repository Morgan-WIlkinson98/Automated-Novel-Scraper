# Novel Scraper Project Guide

This guide is a one-stop reference for the project: what it does, how to install and run it, how the different pieces fit together, and how releases and development are managed.

## What the project does

Novel Scraper watches the NovelUpdates RSS feed for new chapter releases, fetches the actual chapter text from the hosting site, and stores it locally. You can browse, search, and export the stored chapters through a Flask web UI or a packaged desktop application.

High-level flow:

```
NovelUpdates RSS  →  new chapter link  →  link resolver  →  chapter extractor
                                                            ↓
                                          store in SQLite  →  web UI / desktop UI
```

The pipeline is deliberately polite: it respects `robots.txt`, enforces a minimum delay between requests to the same domain, and uses a realistic User-Agent string.

## Main features

- **RSS watcher**: polls NovelUpdates (or any configured RSS feed) and only processes unseen entries.
- **Link resolution**: follows redirects from NovelUpdates to the final hosting page.
- **Chapter extraction**: first tries `trafilatura`, then `readability-lxml`, then a site-specific CSS override.
- **Cloudflare handling**: Playwright can be used as a fallback when a hosting site is behind Cloudflare.
- **Storage**: two SQLite databases:
  - `chapters.db` — stored chapter text and metadata.
  - `seen_entries.db` — deduplication for RSS entries.
- **Web UI**: browse series, read chapters, export EPUBs, and monitor scraper status.
- **Desktop GUI**: the same Flask UI wrapped in a `pywebview` native window, packaged with PyInstaller.
- **NovelUpdates import**: import a NovelUpdates JSON reading-list export so the UI can show current/latest chapter status.
- **EPUB export**: generate EPUB files for a series.
- **Search**: filter the series list by title.

## Installation

### From source (recommended for development)

```bash
# Clone
git clone https://github.com/Morgan-Wilkinson/Automated-Novel-Scrapper.git
cd Automated-Novel-Scrapper

# Create and activate a virtual environment (optional but recommended)
python -m venv .venv
source .venv/bin/activate  # macOS/Linux
# or .venv\Scripts\activate  # Windows

# Install
pip install -r requirements.txt
# or install the package in editable mode
pip install -e .
```

### From PyPI / pip

If a release is published:

```bash
pip install novel-scraper
```

### Packaged desktop release

Download the latest release asset for your platform:

- macOS: `NovelScraper.dmg` — mount and drag `NovelScraper.app` into `/Applications`.
- Windows: `NovelScraper.exe` — run directly.

Releases are published automatically by the GitHub Actions `release.yml` workflow. Source archives are generated by GitHub for every release.

## Configuration

Settings are loaded in this order of priority:

1. Hard-coded defaults in `core/settings.py`.
2. `config.py` in the project root (if present).
3. Environment variables.

Create `config.py` for credentials and site-specific tweaks. Example:

```python
RSS_FEED_URL = "https://rssnovelupdates.com/rss.php?uid=..."
NOVELUPDATES_USERNAME = "your_username"
NOVELUPDATES_PASSWORD = "your_password"

POLL_INTERVAL_SECONDS = 15 * 60  # 15 minutes
MIN_DELAY_SECONDS = 5            # per-domain minimum delay
```

`config.py` is gitignored so your credentials are never committed.

When the packaged desktop app starts, it stores all runtime data (databases, logs, exports, reading-list imports) in `~/.novelscraper` so the app stays writable regardless of where the `.app`/`.exe` is installed.

## Running the project

The `pyproject.toml` installs three console scripts:

| Command                | What it does                                |
|------------------------|---------------------------------------------|
| `novel-scraper`        | Runs the RSS watcher / scraper continuously |
| `novel-scraper-web`    | Starts the Flask web UI on `localhost:6110` |
| `novel-scraper-gui`    | Starts the desktop GUI                      |

You can also run the scripts directly:

```bash
python main.py      # scraper
python web_ui.py    # web UI
python desktop_app.py  # desktop GUI
```

### Desktop app

The desktop app is the easiest way to use Novel Scraper without touching the command line. It launches:

1. The RSS scraper in a background thread.
2. The Flask web server in a background thread.
3. A `pywebview` window pointing at `http://127.0.0.1:6110`.

Data and logs are written to `~/.novelscraper` on macOS/Linux and `%USERPROFILE%\.novelscraper` on Windows.

If the app window is blank, the web server failed to start. Check:

- `~/.novelscraper/logs/app.log` on macOS/Linux
- `%USERPROFILE%\.novelscraper\logs\app.log` on Windows

## Importing a NovelUpdates reading list

NovelUpdates can export your reading lists as JSON. Drop the JSON file into `reading_lists/` (or `~/.novelscraper/reading_lists/` for the packaged app). Run `core/import_nu_export.py` or use the relevant web UI path. The importer creates/updates `series_info` records with:

- `current_chapter_label` and `current_chapter_link`
- `latest_chapter_label` and `latest_chapter_link`
- `reading_list_name`
- `imported_at`

These values are shown on the series list and detail pages.

## Git workflow

This repo uses a feature-branch workflow.

1. Create a feature branch from `main`.
2. Make your changes.
3. Open a Pull Request to `main`.
4. Do **not** push directly to `main` or `dev`.

The `dev` branch is used for pre-release builds. Merging a feature branch into `dev` triggers a `dev` pre-release. Merging into `main` triggers a full release.

## Releases and versioning

The `release.yml` workflow runs on pushes to `main` and `dev` and on `workflow_dispatch`.

- **Main releases**: `1.0`, `1.1`, `1.2`, ... The minor component increments with every merge to `main`.
- **Dev pre-releases**: `1.1-dev.1`, `1.1-dev.2`, ... based on the latest main version.
- **Assets**:
  - macOS: `NovelScraper.dmg` (contains `NovelScraper.app` and an `Applications` shortcut)
  - Windows: `NovelScraper.exe`
  - Source code: `Source code (zip)` and `Source code (tar.gz)` (auto-generated by GitHub)

## Troubleshooting

### The desktop app is a white screen

The web server did not start in time. Check the log file:

- macOS/Linux: `~/.novelscraper/logs/app.log`
- Windows: `%USERPROFILE%\.novelscraper\logs\app.log`

Common causes:

- A permission issue while creating the data directory.
- The scraper thread crashed (see `app.log`).

### macOS says the app cannot be opened because the developer cannot be verified

The `.app` is not signed or notarized. Right-click `NovelScraper.app` and choose **Open**, or remove the quarantine attribute from Terminal:

```bash
xattr -dr com.apple.quarantine /Applications/NovelScraper.app
```

### hdiutil "No space left on device" in the release workflow

This happened in earlier versions because `hdiutil -srcfolder` followed the `Applications` symlink and tried to copy the entire `/Applications` folder. The workflow now creates a temporary read/write image, copies only the `.app`, adds the `Applications` symlink, and then compresses it.

### Cloudflare keeps blocking a series page

The scraper now returns a blocked marker instead of crashing. Cloudflare-protected series will be skipped and logged. You can refresh the browser manually to pass the challenge, or use Playwright if the site requires JavaScript.

### Generic extraction is failing for a specific host

Add a site override in `scraping/site_overrides.py`:

```python
SITE_OVERRIDES = {
    "example.com": {
        "content_selector": "div.chapter-content",
        "remove_selectors": [".ad", ".comments"],
    },
}
```
